# 通知清理器（NotifyCleaner）

一个**只做一件事**的 Android 小应用：**收到指定应用的通知 → 等一会儿 → 把它清掉。**

用来替代 MacroDroid 那个「DSH助手」宏。

---

## 它和 MacroDroid / Automation 的根本区别

| | 前台服务类应用（MacroDroid、Automation） | 本应用 |
|---|---|---|
| 要挂常驻通知吗 | **必须**（Android 强制要求前台服务带通知） | **不需要** |
| 谁负责在进程被杀后拉起 | 应用自己（靠 START_STICKY、KeepAlive 服务、辅助应用、保活折腾） | **系统 + 一个 5 分钟的看门狗闹钟** |
| 抗杀能力 | 普通前台服务，靠厂商白名单续命 | 系统绑定的服务，**难杀得多** |
| 需要授权什么 | 电池优化、自启动、后台运行、厂商白名单一大串 | 一次「通知使用权」+ 建议加个电池白名单 |
| 界面 | 复杂 | 一页设置 + 一页诊断 |

**结论**：MacroDroid 的官方文档自己承认 ——「强制隐藏图标（force hide icon）在某些设备上**已知会导致 MacroDroid 在后台被杀**」。也就是说，它也没法同时做到「看不见」和「杀不死」。

本应用绕开了这个矛盾：**它压根不是前台服务，所以不需要通知来换命。**

## 它是怎么工作的

### 第一版踩过的坑

第一版是「收到通知 → 排一个 10 秒后的定时任务 → 到点清除」。这有个要命的缺陷：

> 那 10 秒里进程要是被系统杀掉，定时任务就跟着没了，通知**永远留着**。

### 现在的写法：按状态判断，不记定时器

```
NotifyCleanerService extends NotificationListenerService

onListenerConnected()  → 立刻巡检一次（补清漏掉的）
onNotificationPosted() → 看一眼，该清的记下来，启动巡检
巡检（每秒一次，只在有待清通知时跑）
    → getActiveNotifications()  问系统"现在还有哪些通知"
    → 逐条判断：是不是监控的应用 / 关键字匹配 / 已存在超过 N 毫秒
    → 到点的就 cancelNotification()，下一轮复查到底清掉没有
```

好处是**没有状态需要保存**：进程被杀，重新连上时再问一次系统就行，该清的补清掉。

### 被系统杀掉怎么办：三道防线

通知监听服务本来由系统（`system_server`）绑定，理论上进程没了系统会重新绑。
但小米 HyperOS / MIUI 这类系统，**划掉多任务时会直接把进程杀掉，而且不一定立刻重新绑**。
所以做了三层兜底：

| 防线 | 做法 | 效果 |
|---|---|---|
| 1. 打开就重连 | 一进应用就自动 `requestRebind`，再观察 3 秒 | 不用再手点「重新连接」 |
| 2. 看门狗闹钟 | 每 5 分钟醒一次，服务没连上就重连。**闹钟由系统保管，进程死了还在** | 即使被杀了，最晚 5 分钟自己恢复 |
| 3. 保活引导 | 一键申请电池优化白名单 + 一键打开各家 ROM 的自启动页 | 从源头上减少被杀 |

其他细节：

- 只清**存在时间在 10 分钟以内**的通知 —— 免得一装上就把几天前的旧通知全清了。
- 常驻通知（音乐播放器那种）不动，因为系统本来就不让清。
- 同一条通知最多试 3 次，还清不掉就记一条警告，不死循环。
- 巡检期间持有一个 `PARTIAL_WAKE_LOCK`（带超时，绝不会漏放），保证这 10 秒里 CPU 不睡。
- **零第三方依赖**：不用 AndroidX，不用 Kotlin 插件，只用 Android 框架自带的 API。

## 关于「关键字」这一项

**飞书通知的结构是：标题 = 「飞书」，正文 = 「DSH助手: 消息内容」。**

所以关键字要能匹配**正文**。第一版把「标题必须包含」「正文必须包含」分成两个框，
按直觉填在标题里就一条都匹配不上，而且界面上完全看不出错在哪。

现在合成**一个框**：`关键字：标题或正文里出现它就算`。填 `DSH助手` 就能匹配到，
不用管它到底在标题还是正文里。老版本填过的值会自动迁移过来，不用重新设。

## 签名与「覆盖安装」（重要）

### 为什么之前装不上新的

GitHub Actions 每次运行都是**全新的机器**，Android 默认的 debug 签名密钥是每台机器现场生成的 ——
所以每次编出来的 APK 签名都不一样，手机上覆盖安装会失败（提示「签名不一致」或「应用未安装」）。

### 现在怎么解决的

仓库里放了一套**固定的签名密钥**（`keystore/notify-cleaner.p12` + `keystore.properties`），
每次编译都用它签。签名固定了，以后所有新版本都能直接覆盖安装，**不用再卸载**。

编译流程里还有一步 `apksigner verify --print-certs`，会把证书指纹打出来 ——
每次编译这个指纹都应该**完全一样**，这就是「能覆盖安装」的证明。

> ⚠️ **装 v3 之前要先卸载一次旧的 v1 / v2**。旧版是随机签名，和新的固定签名对不上，
> 没法覆盖。**只有这一次**需要卸载，之后就不用了。
>
> ⚠️ 仓库是公开的，所以这套密钥和密码也是公开的。对一个自己用的工具 App 可以接受
> （最坏情况是别人也能签一个冒充本 App 的安装包）。想换成私有的：
> 删掉 `notify-cleaner.p12`，用 `keytool -genkeypair` 重新生成一个，改 `keystore.properties` 里的密码。

## 怎么拿到 APK（走 GitHub 云编译，本地零安装）

### 第 1 步：在 GitHub 建一个空仓库

名字随便，比如 `notify-cleaner`。**建的时候不要勾选 README / .gitignore**（勾了会跟下面的推送冲突）。

### 第 2 步：把本目录推上去

在本目录（就是有这个 README 的那一层）打开终端，执行：

```bash
git init
git add .
git commit -m "通知清理器：初版"
git branch -M main
git remote add origin https://github.com/你的用户名/notify-cleaner.git
git push -u origin main
```

> **以后改完代码只要这三条**（可以放心重复粘贴）：
> ```bash
> git add .
> git commit -m "改了什么"
> git push
> ```
> 如果 `git remote add` 报 `remote origin already exists`，说明远程已经加过了，
> 想改地址用 `git remote set-url origin <新地址>`（`add` 是新增、`set-url` 是修改）。
>
> 如果 push 报 `schannel: AcquireCredentialsHandle failed`，换成 OpenSSL 后端：
> `git -c http.sslBackend=openssl push`

### 第 3 步：等它编译

推上去之后，打开仓库页面 → 上方 **Actions** 标签 → 会看到 `build-apk` 正在跑。大约 **1～2 分钟**。

绿勾 = 成功。红叉 = 失败，把报错截图发我。

### 第 4 步：下载 APK

编译完成后，点进那次运行，页面底部 **Artifacts** 区域 → 点 **`notify-cleaner-apk`** 下载。

下载得到的是一个 **zip**，解压出来就是 **`notify-cleaner-v3.0.apk`**。

> ⚠️ 手机浏览器登录 GitHub 下载有时很别扭。建议**在电脑上下载，再传到手机**（微信文件传输助手 / 数据线都行）。

### 第 5 步：装到手机

1. **先卸载旧的「通知清理器」**（只有这一次需要，原因见上面「签名与覆盖安装」）。
2. 把 `notify-cleaner-v3.0.apk` 传到手机，点它安装。
3. 系统会提示「未知来源应用」——允许即可（这是你自己编的，正常）。
4. 装好后**打开一次**。

### 第 6 步：授权「通知使用权」（关键，只做一次）

1. 打开应用，顶部那条状态会显示红色「**● 未授权，无法工作**」。
2. 点「**打开系统「通知使用权」设置**」。
3. 在列表里找到「**通知清理器**」，打开它。
4. 系统可能弹一个「允许此应用读取所有通知？」——选**允许**。
5. 返回应用，顶部应该变成绿色「**● 正在工作**」。

**顶部那条状态是固定的、不跟着滚动**，随时能确认它在不在干活：

| 显示 | 意思 |
|---|---|
| ● 正在工作 | 一切正常 |
| ● 已暂停 | 权限有，但「启用」开关被关了 |
| ● 正在连接服务… | 权限有，正在自动重连（最多等 3 秒） |
| ● 未授权，无法工作 | 权限没给，什么都不会发生 |
| ● 已授权，但服务没连上 | 自动重连没成功 —— 点「重新连接」 |

### 第 7 步：把「保活」那两招点一下（强烈建议）

在「别让系统杀掉它」卡片里：

1. **把本应用设为「不限制后台」** —— 会弹系统对话框，点「允许」。
2. **打开系统的「自启动管理」** —— 在列表里把「通知清理器」打开。

小米 / 华为 / OPPO / vivo 上这两步能明显减少「划掉多任务就失效」的情况。

### 第 8 步：先做一次自检

点「发一条测试通知」，本应用会自己发一条通知，等 10 秒后看它有没有消失，然后直接告诉你结果：

- **✅ 自测通过** —— 整条链路是通的。
- **❌ 自测失败** —— 清不掉。这时去看「最近发生了什么」里的日志，会写清楚断在哪一步。

### 第 9 步：按需要调一下

默认配置已经就是你要的效果：

| 项 | 默认值 | 说明 |
|---|---|---|
| 启用 | 开 | 总开关 |
| 监控这些应用 | `com.ss.android.lark,com.larksuite.suite` | 飞书国内版 + Lark 国际版 |
| 等待毫秒 | `10000` | 就是 MacroDroid 里那个「等待 10 秒」 |
| 关键字 | `DSH助手` | 标题或正文里出现它就算；**留空 = 不过滤，该应用的所有通知都清** |

改完点「**保存**」。

## 出问题了怎么自己定位

界面上的「**最近发生了什么**」会一行一行记下来，最新在最上面。看到这些标记就能判断：

| 日志 | 意思 | 怎么办 |
|---|---|---|
| `🔌 通知使用权已连接` | 服务起来了 | — |
| `👀 收到 飞书｜DSH助手` | 收到了，而且判定要清 | 正常 |
| `➖ 收到 飞书｜xxx → 不清（标题/正文不含关键字）` | **收到了但被关键字挡住了** | 把关键字清空，或者照日志里的真实文字改 |
| `➖ 收到 飞书｜xxx → 不清（不在监控列表）` | 包名不对 | 照日志里的包名改「监控这些应用」 |
| `🧹 清除 飞书｜xxx` | 发起了清除 | 下一行应该是它消失 |
| `⚠️ 清不掉（试了 3 次）` | 系统拦了 | 去系统设置里看本应用的权限 |
| `⏰ 看门狗：服务没连上，已请求重连` | 服务被杀过，看门狗正在救 | 正常；频繁出现就去做第 7 步 |
| 什么都没有 | **通知根本没送到本应用** | 通知使用权没生效，或者服务没连上 |

另外「**当前通知**」卡片会列出系统里现在所有的通知（最多 6 条，带「几秒前」）。这里能看到飞书通知的**真实标题**，也能一键把它们全清掉 —— 即使自动清理坏了，你手动也有个出口。

## 常见问题

**Q：划掉多任务会不会失效？**
通常不会。通知监听服务由系统绑定，不依赖应用自己保活。但国产系统确实可能直接杀进程 ——
所以做了三道防线：打开应用自动重连、每 5 分钟的看门狗闹钟、以及保活引导。真遇到频繁失效，就去做第 7 步。

**Q：需要设置开机自启吗？**
不需要手动设。应用会在开机后自动重新排好看门狗，系统也会重新绑定已授权的通知监听服务。
不过国产 ROM 上还是建议把自启动打开。

**Q：为什么不用 Android Studio？**
因为整个应用只有 6 个 Java 文件 + 十几个小资源文件，用命令行编译就够了，没必要为此下载几个 GB 的 IDE。

**Q：以后想改功能怎么办？**
改完代码 `git push`，Actions 会自动重新编译，再去 Artifacts 下载新的 APK **直接覆盖安装**即可。

**Q：想本地编译（不走云）？**
需要自己装 JDK 17 + Android SDK 命令行工具（约 1.5–2 GB），然后在工程目录执行：

```bash
gradle assembleRelease
```

产物在 `app/build/outputs/apk/release/app-release.apk`。
